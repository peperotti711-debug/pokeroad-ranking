# 完走ランキング — GitHub Pages + Firebase

## 公開前に必要な設定

1. [Firebase Console](https://console.firebase.google.com/) でプロジェクトを作る。
2. プロジェクト設定で「ウェブアプリ」を追加し、表示された `firebaseConfig` の各値を `firebase-config.js` にコピーする。
3. Authentication → Sign-in method → **メール/パスワード** を有効化する。アカウントIDから内部的にダミーメールアドレスを作って認証します（実際のメール送信は使いません）。
4. Firestore Database を作成し、「ルール」画面に `firestore.rules` の内容を貼り付けて公開する。
5. Storage を有効化し、「ルール」画面に `storage.rules` の内容を貼り付けて公開する。**Firebase Storage は利用開始に課金アカウントの登録が必要な場合があります。** 料金・無料枠を確認してください。
6. Authentication → Settings → Authorized domains に GitHub Pages のドメイン（`ユーザー名.github.io`）を追加する。
7. GitHub リポジトリのルートに `index.html`, `app.js`, `firebase-config.js`, `example.png` をアップロードする。Settings → Pages → Deploy from a branch → main / (root) → Save。

`firestore.rules` と `storage.rules` は GitHub Pages では直接適用されません。**必ずFirebase Consoleに貼り付けて公開**してください。

## 仕様

- アカウント作成：名前・アイコン・英数字を含む8文字以上のパスワード。自動発行されるアカウントIDも保存カードに含みます。
- 画像カード：パスワードとIDをQRに埋め込むため、**カード画像を持つ人はログインできます**。他人と共有しないでください。
- カードは「画像として保存」からPNG生成でき、生成画像を長押し保存することもできます。ブラウザの制限で画像保存動作が異なる場合があります。
- 投稿：完走画像・残り手数・編成。画像の自動判定は行いません。
- ALL / 今月：編成ごとに各ユーザーの最高記録1件を表示。同点の場合は投稿日時が早い方を上位にします。
- 月別順位：投稿の作成日時から月別集計します。投稿は編集・削除不可なので過去月の順位は確定します。月が変わってからユーザーが最初にサイトを開いた際に先月の各カテゴリの順位をダイアログ表示します。同じ月に同じ端末・ブラウザで再表示しないようlocalStorageに記録します（別端末では再表示されます）。月末のサーバー側スナップショット保存は未実装です。
- 投稿後の削除・編集、通報、モデレーション、パスワード再発行は未実装です。
- 現状は小規模向けで、すべての投稿とプロフィールを読み込みブラウザで集計します。利用者が増えたらサーバー側の集計・ページングが必要です。
- パスワードはFirebase Authenticationで管理され、Firestoreに平文保存しません。ただし保存カード画像にはパスワードが記載されます。
- 名前は重複可能です。ログインにはアカウントIDとパスワード、またはカード画像を使います。
- Firebaseの課金・利用上限・セキュリティルールを確認して運用してください。


## 運営アカウントの設定（必須・安全な方式）

**運営用パスワードをHTMLやJavaScript、Firestoreルールに直接書かないでください。** 公開サイトのソースから誰でも読めてしまいます。運営権限はFirebase Authenticationのカスタムクレーム `admin: true` で確認します。

1. 公開したサイトで、運営専用の通常アカウントを一つ作り、ログインカードを安全に保存する。パスワードは他人に知らせず、使い回さない。
2. Firebase Console → Authentication → Users でそのアカウントを探し、**UID** を控える。
3. ローカルPCの安全な作業フォルダで `npm install firebase-admin` を実行する。Firebase Console → プロジェクト設定 → サービスアカウントで管理用の秘密鍵JSONを取得し、**GitHubに絶対アップロードしない**。
4. 同梱の `set-admin.mjs` と秘密鍵JSONを同じローカルフォルダに置き、`node set-admin.mjs <運営アカウントのUID> <秘密鍵JSONのパス>` を実行する。**この操作は自分が管理するFirebaseプロジェクトだけで実行**する。
5. Firebase ConsoleのFirestore/Storageルールを同梱の更新版に置き換えて公開する。**古いルールのままだと削除できません**。
6. 運営アカウントでログアウト→再ログインすると「運営管理」タブと「運営アカウント」の表示が出る。

削除はFirestoreの投稿データを削除した後、Storageの投稿画像も削除します。画像削除が失敗した場合は孤立ファイルが残る可能性があり、ブラウザの開発者コンソールに警告が出ます。ランキングとプロフィールは投稿の再取得で更新されます。

**注意：** 管理用秘密鍵JSONは厳重に保管し、公開リポジトリや共有ZIPに含めないでください。運営アカウントの権限を剥奪するには管理SDKからカスタムクレームを変更します。既存の一般ユーザーに運営権限は付与されません。
